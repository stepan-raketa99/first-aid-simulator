# Рядом — первая помощь в действии

Браузерный образовательный 2D-симулятор для университетской работы по БЖД. Пять ситуаций со взрослыми пострадавшими, **по одной последовательной истории на уровень**, полноценные базовые мероприятия и наглядные схемы. Проект продолжает исходное приложение: HTML, CSS, ES Modules и оригинальные SVG по `reference.jpg`.

## Запуск

Нужен **Node.js 22+**. Устанавливать зависимости и собирать приложение не требуется.

```sh
npm start
```

Откройте **http://localhost:4173**. Остановка сервера — `Ctrl+C`.

Альтернатива при наличии Python:

```sh
python -m http.server 4173 --bind 127.0.0.1
```

Нужен только статический HTTP-хостинг для ES Modules. Открытие `index.html` через `file://` ограничивается браузерами. Серверной логики, регистрации, базы данных, платных API и обязательного интернета для работы игры нет.

## Как проходить

1. Выберите ситуацию на главном экране.
2. В каждом уровне заранее задано одно конкретное состояние пострадавшего; выбора альтернативного развития событий нет.
3. Выполняйте конкретные действия кнопками нижней панели или через отмеченные объекты сцены. Неуместные действия заблокированы, выполненные исчезают.
4. При необходимости откройте «Техника и источники»: там подробности приёма и прямые ссылки на официальные материалы.
5. После короткой визуальной последовательности следующий этап открывается автоматически, без кнопки «Продолжить». В конце — памятка, повтор и следующий уровень.

Реплики находятся только над говорящими. Инструкции и краткий результат — в нижней панели. Персонаж помощника статичен; изменения касаются пострадавшего и средств помощи. Переходы между целостными позами не деформируют конечности. Поддерживается `prefers-reduced-motion`.

Нет штрафов, игровых дедлайнов или случайного ухудшения. Проверка дыхания «не более 10 секунд» и параметры СЛР в памятке относятся к реальной первой помощи. В выбранной истории человека без сознания нормальное дыхание сохранено, СЛР не проводится.

### Пять фиксированных историй

| Ситуация | Состояние и основное содержание |
| --- | --- |
| Без сознания | Нормальное дыхание сохранено: безопасность, осмотр, реакция, дыхательные пути, оценка дыхания, боковое положение, вызов, наблюдение и передача. |
| Кровотечение | Прямое давление и повязка эффективны: безопасность, перчатки, выявление источника, давление и поручение вызова, проверки эффективности, повязка, положение, контроль. Показаний к жгуту в этой истории нет. |
| Травма предплечья | Сознание и дыхание сохранены: опрос, осмотр на другие травмы, вызов, покой, поддержка и выполнимая фиксация в найденном положении, холод, контроль. |
| Признаки инсульта | Сознание и нормальное дыхание сохраняются. Срочный вызов до дополнительных проб, улыбка/речь/руки, время, положение и наблюдение. |
| Переохлаждение | Заторможенность с нормальным дыханием: опасные признаки, вызов, бережное перемещение, изоляция, сухая одежда, одеяло и постепенное согревание, контроль. Питьё не предлагается. |

В сохранённых историях осталось прежнее число действий: 9, 10, 12, 11 и 11 соответственно — всего 53. Дополнительных действий не добавлено. Все уровни можно запускать и повторять в любой момент.

`14:20` — учебный факт очевидца о последнем нормальном состоянии, а не время пользователя.

## Медицинская основа и границы

Прочитана полная пятистраничная копия приказа № 220н на сайте МЧС, материалы МЧС по СЛР, боковому положению, кровотечениям, травмам и переохлаждению, материалы официального портала Минздрава «Так здорово» о СЛР и признаках инсульта.

**Не всё содержание получило одинаковую степень подтверждения.** Точный порядок использования конкретной модели АНД, некоторые специальные положения об инсульте, режим охлаждения и критерии питья при переохлаждении требуют дополнительной предметной сверки. Расхождения о длительном наложении жгута и о горячем/тёплом питье не выдаются за универсальные правила.

Полная матрица утверждений, доступность источников, SHA-256 полученного приказа, решения по расхождениям и оставшаяся проверка — в **[MEDICAL_REVIEW.md](MEDICAL_REVIEW.md)**. Автотесты подтверждают работу алгоритма и интерфейса, но не заменяют проверку медицинского содержания инструктором. Игра не удостоверяет практические навыки СЛР, применения жгута и других приёмов. В экстренной ситуации — **112 или 103** и указания диспетчера.

```text
src/app.js                  Экраны и проигрывание действий
src/scene.js                Исходное городское окружение и композиция сцен

src/clinical.js             Схемы СЛР/АНД, жгут, записка, средства фиксации
src/dialogue.js             Облачка над говорящим, учёт лиц и границ экрана
src/animation.js            Смена поз и жёсткие переходы без морфинга костей
src/medical.js              Каталог реально просмотренных официальных источников

```

### Изменение сценариев

`level.context` задаёт состояние пострадавшего, `level.steps` — единственную последовательность действий. `requires` указывает предыдущее действие, `needsEffects` при необходимости проверяет медицинское условие. Движок разрешает только следующий шаг; `terminal` завершает историю после необходимых действий.

Фазы `frames` содержат `effect`, `caption`, отдельную `dialogue`, дополнительные эффекты `also` и снимаемые состояния `clear`. Общая функция `applyFrame` используется движком и визуальным проигрывателем. `record` удерживает учебные медицинские факты только для текущего происшествия.

Панель показывает доступные действия и два ближайших заблокированных, а не длинный список всех будущих кнопок. Детальные сведения открываются по необходимости. Медицинские изменения должны сопровождаться обновлением `MEDICAL_REVIEW.md` и проверками клинических зависимостей.

### Отсутствие истории прохождений

Приложение не обращается к localStorage, не хранит историю уровней и не восстанавливает прежние отметки. Состояние текущего действия остаётся только в памяти до возврата или повторного запуска. Персональные данные и аналитика не собираются. Поддерживаются клавиатурные `Tab`, `Enter` / `Space`; информационный диалог закрывается через `Escape`.

## Проверки

```sh
npm run check
npm test
npm run test:browser
```

Первые две команды не требуют браузера. Браузерная проверка использует установленный Google Chrome по стандартному пути Windows; иной путь — переменная `CHROME_PATH`. Нужны свободные порты 4173 / 9333. Перед проверкой закройте ранее запущенный сервер игры. Playwright и другие пакеты не нужны.

Проверки охватывают:

- синтаксис девяти модулей;
- 11 автотестов: пять единственных последовательностей, прежние 53 действия, зависимости, запрет пропусков и повторов, отсутствие ненужной СЛР или жгута в выбранных состояниях;
- отсутствие чтения/записи localStorage и истории в движке, повтор и возврат;
- реальные клики в Chrome при 1440 и 390 px, все пять уровней на каждой ширине, доступность/блокировки кнопок;
- SVG как XML, промежуточные жёсткие повороты головы, отсутствие деформируемых конечностей и анимации помощника, размещение реплик над правильным говорящим без перекрытия лиц;
- возврат, повтор, следующий уровень, перезагрузку, отсутствие отметок и переключателей, игнорирование старой истории, отмену анимации при выходе и отсутствие необработанных исключений JS;
- `prefers-reduced-motion`.

Вручную остаются Safari/Firefox, реальные iOS/Android, экранный диктор и очная оценка медицинской и художественной читаемости схем инструктором. Такие проверки не подменяются headless Chrome.

Инструмент `tools/medical-sources.py` не нужен для запуска и тестов игры. Он использует Python standard library для HTML и отдельно доступный `pypdf` для чтения PDF; во время разработки библиотека была установлена во временную папку вне проекта.
